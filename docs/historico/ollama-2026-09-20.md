```text

```

```ini
[Service]

Environment="OLLAMA_NUM_THREADS=6"

TimeoutStopSec=10
KillMode=control-group
```

Comandos utilizados:

```bash

sudo systemctl start ollama.service
systemctl show ollama --property=Environment
```

```bash

sudo tee /etc/systemd/system/ollama.service.d/override.conf > /dev/null <<'SYSTEMD_EOF'

Environment="OLLAMA_KEEP_ALIVE=30m"
Environment="OLLAMA_NUM_THREADS=6"
```

## Problema de parada observado

Durante un reinicio anterior, un `llama-server` antiguo no terminó a tiempo:

```text
ollama.service: State 'final-sigterm' timed out
Killing process ... llama-server ... with signal SIGKILL
```

Se añadió:

```ini
TimeoutStopSec=10
KillMode=control-group
```

Comprobación de procesos:

```bash
pgrep -af 'ollama|llama-server' || true
```

Un proceso `<defunct>` es un zombie; no se elimina directamente con `kill`.

## Descarga del modelo 7B

```bash

```

Mientras `ollama pull` está activo no se debe reiniciar Ollama ni ejecutar `pkill`, porque el cliente necesita que el servidor permanezca disponible.

Comprobaciones seguras desde otra terminal:

